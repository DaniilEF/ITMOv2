## Context Pack для первого рабочего сценария

### Факты и правила

- SEC-1: перед отправкой во внешний LLM из diff удаляются токены, пароли и приватные ключи. Источник: CASE.md.
- API-1: diff длиннее 20 000 символов отклоняется с HTTP 413. Источник: CASE.md.
- REL-1: внешний LLM-вызов имеет timeout 10 секунд; ошибка превращается в контролируемый ответ. Источник: CASE.md.
- OUT-1: ответ содержит `summary`, `risks` (≤3, c `file`, `line`, `evidence`, `risk`) и `checks`. Источник: CASE.md.
- SCOPE-1: сервис только советует; он не пишет код и не выполняет действия в GitHub. Источник: CASE.md.
- QA-1: риск включается только при подтверждении строкой diff или правилом. Источник: CASE.md.

### Формат входа и результата

- Вход: HTTP POST `/api/reviews` с полем `diff` (строка). Источник: TRAINING_PR.diff (app/api.py:35-38).
- Результат: по правилам OUT-1 — `summary`, `risks`, `checks` (текущая реализация возвращает `{comment}` — несоответствие). Источник: TRAINING_PR.diff (app/review_service.py:23), CASE.md.

### Ограничения и запрещённые действия

- Запрещено: approve, merge, edit; добавлять новые правила вне SEC-1..QA-1. Источник: CASE.md.
- Сервис не логирует содержимое diff/ответа модели (OBS-1). Источник: CASE.md.

### Хороший пример

app/review_service.py:16 — diff отправляется во внешний LLM без удаления секретов, что нарушает SEC-1. Проверка: передать diff с тестовым token и убедиться, что в prompt осталось [REDACTED]. Источник: CASE.md.
### Плохой пример

«Код можно улучшить. Добавьте тесты и обработку ошибок.» — нет ссылки на файл/строку и правила. Источник: CASE.md.
### Что пока неизвестно

- Где реализуется редактирование/санитайз diff перед LLM (если предусмотрено) — в текущем diff этого нет.
- Требуемая версия Python и совместимость с типами `dict[str, str]`.
- Наличие аутентификации/ограничений доступа к эндпоинту.

## Как использовали AI

- Для чего: анализ учебного diff PR и составление рисков/проверок.
- Тип промпта: Zero-shot (P1-01) и Master prompt (P1-02).
- Строка в [`prompts.md`](prompts.md): P1-01, P1-02.
- Что проверили и исправили сами: проверили соответствие выводов строкам diff и правилам CASE.md; исключили предположения без evidence; оформили master prompt и контекст.
