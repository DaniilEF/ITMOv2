1. Вердикт
Модель угроз в целом пригодна к использованию: системная картина, границы доверия, DFD и покрытие STRIDE/LLM сделаны хорошо, угрозы привязаны к коду и снабжены проверками. Главные риски: неавторизованный/чрезмерный доступ executor’а (E-2, T-5, D-1), SQL-инъекции (T-1..T-3), утечки через логи (I-2) и prompt injection с небезопасным исполнением решений (L-1, L-2, L-6). Есть несколько пробелов: нет владельцев активов, отсутствуют явные меры по I-5 (утечка данных в prompt), не все меры сформулированы проверяемо. Уверенность высокая, с оговоркой по неуказанным деталям токенов/TTL и поведению sandbox для symlink’ов.

2. Сильные стороны
- Чёткая схема системы и границ (разделы 1.1–1.3, DFD в разделе 2), фиксация ключевой особенности executor’а (строки 96–97).
- Полное покрытие SQLi, IDOR, XSS, path traversal, утечек и DoS с привязкой к строкам кода (раздел 3: T-1..T-6, I-1..I-4, D-1..D-2).
- Внятная декомпозиция LLM-рисков и их связь с потоками и кодом (раздел 4: L-1..L-6).
- Меры и проверки оформлены по большинству угроз с критериями приёмки (разделы 4.1 и 5).

4. Пропущенные угрозы
| Актив/поток | STRIDE или LLM | Сценарий | Мера | Проверка |
|---|---|---|---|---|
| A5 (токены) | Spoofing | Предсказуемые/долгоживущие токены позволяют угадать/перехватить сессию (допущение) | Криптографическая генерация, TTL, отзыв, привязка к субъекту | Токен ≥128 бит энтропии; истечение по TTL; негативные тесты угадывания |
| TB5: клиент → executor | Repudiation | Реплей решения между запросами/сессиями без nonce | Ввести nonce в контекст и требовать его в execute; логировать связку session-id/nonce | Неверный/повторный nonce → 400; корректный → 200 |
| TB4: API → LLM | DoS | Много параллельных /assistant/context перегружают shop-planner (допущение) | Rate limit, пул/очередь, таймаут внешнего процесса | >N rps возвращает 429; средняя задержка остаётся в допуске |
| A10 (логи) | Repudiation/Tampering | Подмена/подделка записей через инъекции разделителей строк в полях запроса | Нормализация/экранирование значений перед логированием, формат JSON Lines | Наличие CR/LF в вводе не ломает формат и не создаёт фальш-записей |
| TB4/TB3 (sandbox) | Tampering/Information disclosure | Symlink traversal в каталоге пользователя для чтения чужих файлов (допущение) | Проверять realpath против корня пользователя; запрещать/удалять symlink | Попытка чтения через symlink → 403/404 |

7. Оценка
8/10 — Активы и потоки описаны полно (1.5/2), покрытие STRIDE хорошее с привязкой к коду (1.8/2), LLM-угрозы учтены и детализированы (1.8/2), меры в целом адекватны, но часть непроверяема/неполна (1.3/2), хорошая доказательность и согласованность, но есть невязки (I-1, I-5) (1.6/2).

- Устранить SQLi и IDOR: параметризованные запросы, типизация входов, обязательная сессия и проверка владельца для всех чувствительных маршрутов (T-1..T-3, S-2/E-4).
- Защитить логи и журнал: закрыть /debug/logs, редактировать секреты, добавить аудит с субъектом и отказаться от выдачи внутренних ошибок клиенту (I-2, R-1/R-2, I-4).
- Минимизировать LLM-контекст и защититься от prompt injection: разделение инструкций/данных, исключение чужих данных из контекста, серверная валидация решений и привязка к nonce (L-1, I-5, L-2, L-6).
