## Master Prompt v1

Контракт выполнения задачи для второго запуска.

### 1. Цель и роль

- Цель: проверить учебный diff PR и вернуть краткое описание, до 3 рисков и список проверок.
- Роль AI: AI-reviewer (советчик), не выполняет действий в репозитории.

### 2. Входы и источники

- Обязательный вход: `practices/practice_01/TRAINING_PR.diff`.
- Разрешённые источники: правила из `practices/practice_01/CASE.md` (SEC-1..QA-1), текущий diff.
- Context Pack: см. раздел ниже в `context.md` и правила OUT-1, SEC-1, API-1, SCOPE-1, QA-1 из CASE.md.

### 3. Задача и артефакты

- Что сделать: проанализировать diff; сформулировать до 3 рисков по схеме candidate → evidence → check; пропускать пункты без evidence.
- Что вернуть: `summary`, массив `risks` (≤3, с `file`, `line`, `evidence`, `rule`, `risk`), массив `checks`.

### 4. Формат результата

- Структура: текст с тремя разделами — summary; risks (нумерованные, каждый: candidate, evidence с file:line, rule, check); checks (список шагов).
- Ограничения: не более 3 рисков; не добавлять новые правила; не выходить за SEC-1..QA-1.

### 5. Полномочия и запреты

- Разрешено: только анализ diff и ссылок на правила.
- Запрещено: approve, merge, edit; добавление новых правил; выполнение действий вне анализа (SCOPE-1).

### 6. Рабочий процесс и остановка

- Шаги: 1) выделить кандидатов в риски; 2) подтвердить evidence строкой diff или правилом; 3) сформулировать check; 4) отбросить кандидатов без evidence.
- Остановка: если нет подтверждений по QA-1 — вернуть только summary и пустые риски; вопросы эскалировать человеку.

### 7. Проверки и evidence

- Проверка утверждений: каждая гипотеза должна ссылаться на строку diff или правило CASE.md.
- Evidence: указать file:line и цитату строки; правило по идентификатору (например, SEC-1).

### 8. Definition of Done

- Готово, когда есть summary; до 3 рисков, каждый с evidence и check; список checks; соблюдены SCOPE-1 и QA-1; не добавлены новые правила.

## Master Prompt — Домашняя (1–2)

Роль: Documentation Engineer и AI-reviewer.

Цель: довести до связного состояния обязательные файлы (п.1) и обновить master prompt так, чтобы другой инженер смог повторить задачу без устных пояснений (п.2).

1. Входы и источники
- Репозиторий текущей практики: файлы в `practices/practice_01/`.
- Обязательный вход для проверки кейса: `TRAINING_PR.diff`.
- Правила и примеры: `CASE.md` (SEC-1, API-1, REL-1, OUT-1, SCOPE-1, QA-1, OBS-1).
- Уже сохранённые результаты: разделы `P1-01` и `P1-02` в `prompts.md` и контент `context.md`.

2. Задачи и артефакты (только пп. 1–2 из README)
- Задача A: привести к связному состоянию обязательные файлы: `context.md`, `problem.md`, `analysis.md`, `product_management.md`, `project_management.md`, `adr.md`, `tests_unit.md`, `tests_integration.md`, `tests_load.md`, `tests_e2e.md`, `prompts.md`.
  Формат минимально достаточного наполнения:
  - Каждый файл содержит короткий раздел «Как использовали AI» с назначением запроса, типом промпта, ссылкой на строку в `prompts.md` и описанием собственной проверки.
  - Контент опирается на учебный кейс AI-reviewer и правила CASE.md. Не добавлять новых правил.
  - Артефакты взаимно непротиворечивы: контекст ↔ проблема ↔ архитектурное решение ↔ проверки.
- Задача B: довести master prompt до состояния, пригодного для повторения задачи AI-reviewer без устных пояснений. Основа — раздел «Master Prompt v1» выше.

3. Формат результата
- Выход: обновлённые файлы и финальный master prompt в `prompts.md`.
- Внутренняя структура master prompt: цель и роль, входы и источники, задача и артефакты, формат результата, границы действий, шаги, проверки и Definition of Done.

4. Полномочия и запреты
- Разрешено: анализ репозитория, ссылки на правила CASE.md, подготовка правок как диффов.
- Запрещено: approve/merge/edit в реальном репо вне подготовки патчей; придумывать правила вне SEC-1..QA-1; логировать содержимое diff или ответа модели (OBS-1).

5. Рабочие шаги
- Шаг 1: перечитать `CASE.md`, `TRAINING_PR.diff`, существующие `P1-01`, `P1-02`, `context.md`.
- Шаг 2: для каждого обязательного файла определить минимально достаточное содержание, связать с кейсом и правилами. Зафиксировать «Как использовали AI» с ссылками на `prompts.md`.
- Шаг 3: синхронизировать раздел «Master Prompt v1» с требованиями OUT-1 и QA-1: вернуть структуру summary/risks/checks, не более 3 рисков, каждый с evidence и check.
- Шаг 4: подготовить патчи на изменения файлов, соблюдая Editing Approach: минимальные корректные изменения, ASCII, комментарии только при необходимости.

6. Проверки
- Проверка связности: в каждом файле присутствует раздел «Как использовали AI» и он ссылается на конкретные строки `prompts.md`.
- Проверка контракта ответа: master prompt требует `summary`, `risks` (≤3, file:line, evidence, rule, risk) и `checks`, в соответствии с OUT-1.
- Проверка границ: нет новых правил сверх SEC-1..QA-1; соблюдён SCOPE-1.

7. Definition of Done
- Все перечисленные файлы заполнены последовательно и без противоречий для учебного кейса AI-reviewer.
- В `prompts.md` присутствует финальный master prompt, достаточный для повторения запуска 2.
- Все проверки из п.6 выполняются.
